# 用户端团队工作范围

团队选择器读取当前登录用户的有效团队成员关系。选择保存在用户与工作区维度，刷新时重新验证成员关系。没有团队时，团队数据展示空态，不回退到整个工作区资源；组织 Skill 目录仍可浏览，但没有可安装目标。

切换团队跳转至人才与技能页面并重新加载文档，使旧请求、运行入口缓存、已打开预览与临时附件结束生命周期。新的团队在数据加载前完成验证。

- 数字员工：展示归属团队的已发布员工，以及启用在该团队的员工入口。运行仅使用当前团队入口。
- Skill：展示管理端 `/skills/catalog` 返回的当前组织（`workspace_id`）完整授权目录，不再按 `/skills/spaces/list` 的团队绑定过滤，切换团队不改变目录。安装菜单和操作只接受当前团队内已创建的数字员工及未归档群组项目。
- 安装记录目前仍使用既有用户端本地存储，按账号、组织、团队隔离；本次不新增服务端安装接口，也不改变服务端授权。
- 对话：`commands/work` 指定团队范围，只读取范围匹配的对话详情。
- 文件：使用团队 `space_id` 读取知识资源及资源内文件，支持原生模块和历史文档列表分页。真实文件的查看操作打开现有管理端资源详情；未接入文件内容的情况下不伪造下载或附件引用。
- 群组项目、文件夹、本地上传、员工别名、隐藏状态、已安装记录和消息标记：按用户及团队分别存储。此前没有团队归属的旧缓存保留原键，不猜测归属或复制到所有团队。

验证入口：`pnpm test` 覆盖团队数据隔离、无团队空态、记忆选择、账号隔离及成员撤销；`pnpm build` 校验类型和构建。

真实验收：选择团队，检查员工、文件、对话及 Skill 安装目标跟随团队变化，组织 Skill 目录保持一致；刷新验证选择不变；切回原团队检查项目、安装记录和个人设置恢复。只有一个有效团队时不提供切换菜单。应使用具有两支团队及不同资源的专用验收账号进行完整多团队浏览器验收。`scripts/team-scope.test.mjs` 和 `scripts/skill-install-scope.test.mjs` 覆盖组织目录与安装范围的分离、跨团队目标拒绝和安装记录隔离。
